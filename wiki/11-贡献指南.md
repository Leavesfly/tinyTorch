# 11 · 贡献指南

欢迎参与 tinyTorch！本项目以**教学与原理透明**为第一目标，任何能让代码更清晰、文档更易懂、测试更完备的贡献都会被认真对待。

本文依次介绍：**贡献类型 → 环境搭建 → 开发流程 → 代码规范 → 测试要求 → 提交 & PR 规范 → 发布流程 → 行为准则**。

---

## 11.1 贡献类型

tinyTorch 欢迎以下类型的贡献（难度由低到高）：

| 类型 | 示例 | 入门友好度 |
|------|------|------------|
| **文档修订** | 修错别字、澄清表述、补示例、翻译 | ⭐⭐⭐⭐⭐ |
| **单元测试** | 给未覆盖的分支补测试、加 `gradcheck` 用例 | ⭐⭐⭐⭐ |
| **Bug 修复** | 修复 issue、补充边界处理 | ⭐⭐⭐ |
| **性能优化** | 在纯 Python 约束下优化热点循环 | ⭐⭐⭐ |
| **新算子 / 新层** | 实现新的 `Function` 子类或 `Module` 层 | ⭐⭐ |
| **新示例** | 在 `examples/` 下新增端到端样例 | ⭐⭐ |
| **核心架构** | 改动自动微分、计算图、模块注册机制 | ⭐ |

> **建议**：首次贡献优先从**文档**或**测试补齐**入手，便于熟悉仓库节奏；核心架构类改动请先开 issue 讨论。

## 11.2 开发环境搭建

### 11.2.1 基础要求

- **Python** ≥ 3.7（CI 覆盖 3.7 / 3.8 / 3.9 / 3.10 / 3.11）
- **Git**
- 一个你喜欢的 IDE（推荐 PyCharm / VS Code）

### 11.2.2 克隆并安装

```bash
# 1. Fork 仓库到自己的账号下，然后克隆
git clone https://github.com/<your-username>/tinyTorch.git
cd tinyTorch

# 2. 添加上游远端，方便同步官方改动
git remote add upstream https://github.com/Leavesfly/tinyTorch.git

# 3. 创建并激活虚拟环境
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# 4. 以"可编辑模式"安装本项目及开发依赖
pip install -e ".[dev]"
```

`[dev]` extras 会拉入：

| 包 | 版本约束 | 用途 |
|----|----------|------|
| `pytest` | `>=6.0` | 单元测试 |
| `pytest-cov` | `>=2.10` | 覆盖率统计 |
| `ruff` | `>=0.4.0` | 静态检查 + 格式化 |

tinyTorch 本身**无运行时依赖**，安装后运行 `import tinytorch` 即可使用。

### 11.2.3 同步上游

在开始写代码之前，务必把 `main` 对齐最新：

```bash
git checkout main
git fetch upstream
git rebase upstream/main
git push origin main
```

## 11.3 开发流程

### 11.3.1 一次贡献的完整生命周期

```
  ┌────────────────────┐
  │  fork & clone      │
  └──────────┬─────────┘
             ↓
  ┌────────────────────┐
  │  create a branch   │   feat/<topic>  fix/<topic>  docs/<topic>
  └──────────┬─────────┘
             ↓
  ┌────────────────────┐
  │  implement + test  │   ← 必须含单元测试
  └──────────┬─────────┘
             ↓
  ┌────────────────────┐
  │  ruff + pytest     │   ← 本地自测全绿
  └──────────┬─────────┘
             ↓
  ┌────────────────────┐
  │  commit & push     │   ← 遵守 Commit 规范
  └──────────┬─────────┘
             ↓
  ┌────────────────────┐
  │  open Pull Request │   ← 填写 PR 模板
  └──────────┬─────────┘
             ↓
  ┌────────────────────┐
  │  review & merge    │
  └────────────────────┘
```

### 11.3.2 分支命名

| 前缀 | 用途 |
|------|------|
| `feat/` | 新功能（新算子、新层、新工具） |
| `fix/` | Bug 修复 |
| `docs/` | 纯文档改动 |
| `test/` | 仅加测试或改测试 |
| `refactor/` | 不改行为、只改组织的重构 |
| `perf/` | 性能优化 |
| `chore/` | 构建、CI、杂项 |

示例：`feat/softmax-op`、`fix/linear-3d-reshape`、`docs/autograd-topo-sort`。

### 11.3.3 快速自测组合

**最小自测**（提交前必跑）：

```bash
# 静态检查
ruff check .

# 全量单元测试
python run_tests.py
```

**常用快捷命令**：

```bash
# 只跑一个测试文件（run_tests.py 支持位置参数，不带 .py 后缀）
python run_tests.py test_autograd

# 只跑一个测试类（直接用 pytest）
pytest tests/test_autograd.py::TestBackward -v

# 只跑一个测试函数
pytest tests/test_autograd.py::TestBackward::test_simple_backward -v

# 统计覆盖率
pytest --cov=tinytorch --cov-report=term-missing

# 自动修复能修的 lint 问题
ruff check --fix .
```

## 11.4 代码规范

### 11.4.1 静态检查：`ruff`

项目在 `pyproject.toml` 中配置了 `ruff`，启用以下规则集：

| 规则族 | 说明 |
|--------|------|
| `E` / `W` | pycodestyle 错误 / 警告 |
| `F` | pyflakes（未使用的导入、未定义的变量） |
| `I` | isort（`import` 顺序） |
| `UP` | pyupgrade（可升级的语法） |
| `B` | flake8-bugbear（常见隐患） |
| `SIM` | flake8-simplify（可简化的写法） |
| `RUF` | ruff 自带规则 |

已**豁免**的规则（`ignore`）：

| 规则 | 豁免原因 |
|------|----------|
| `E501` | 行长度交给格式化处理 |
| `B905` | `zip(..., strict=True)` 是 3.10+ 特性，保兼容 3.7 |
| `UP007` | `Optional[X]` / `Union[X, Y]` 写法保兼容 3.7 |
| `SIM108` | "三元表达式替代 if/else" 不强制，优先可读性 |

行长度上限设置为 **120** 列（见 `[tool.ruff] line-length = 120`）；超出的长字符串、注释用多行书写。

### 11.4.2 命名与风格

沿用标准 PEP 8 并结合本仓库的既有风格：

- **模块 / 文件名**：`snake_case.py`
- **类名**：`PascalCase`（例：`LayerNorm`、`DataLoader`）
- **函数 / 方法 / 变量**：`snake_case`
- **常量**：`UPPER_SNAKE_CASE`（例：`tinytorch/constants.py`）
- **私有实现**：以 `_` 开头（不在公共 API 中导出）
- **类型注解**：所有公共函数、方法、`Module.forward` 都应带完整的 `typing` 注解。

### 11.4.3 `import` 约定

`ruff` 的 `isort` 规则会自动排序，本项目将 `tinytorch` 视为 **first-party**：

```python
# 1. 标准库
import math
from typing import List, Optional

# 2. 第三方（tinyTorch 无运行时依赖，通常为空）

# 3. 本项目
from tinytorch.ndarr import NdArray, Shape
from tinytorch.autograd.tensor import Tensor
```

**三块之间用空行分隔**；在跨模块 import 时优先使用**绝对路径**（`from tinytorch.xxx import ...`），不要写 `from ..xxx import ...`。

### 11.4.4 文档字符串

公共类、函数必须有 docstring，推荐使用 **Google 风格**（与仓库现有代码一致）：

```python
def matmul(self, other: 'NdArray') -> 'NdArray':
    """二维矩阵乘法。

    Args:
        other: 另一个二维 NdArray，`self.shape[-1] == other.shape[0]`。

    Returns:
        形状为 `(self.shape[0], other.shape[1])` 的新 NdArray。

    Raises:
        NotImplementedError: 当任一输入的维度不是 2 时抛出。
    """
```

- 公式或数学表达优先以**中文 + LaTeX** 方式写入 docstring；
- `Raises` 小节必须列出显式 `raise` 的异常。

### 11.4.5 禁忌

以下写法在 PR 中会被要求修改：

- ❌ `from tinytorch.xxx import *`（遮蔽符号来源）
- ❌ 裸 `except:` / `except Exception: pass`（吞异常）
- ❌ 硬编码常量散落在多个文件（应提取到 `tinytorch/constants.py`）
- ❌ 遗留 `TODO` 注释、`print("debug ...")`、`import pdb` 等调试痕迹
- ❌ 在 `tinytorch/` 中直接依赖 `numpy`、`torch` 等第三方库（**禁止引入运行时依赖**）

## 11.5 测试要求

### 11.5.1 目录约定

所有测试位于 `tests/`，文件命名 `test_<module>.py`，当前覆盖：

| 测试文件 | 负责模块 |
|----------|----------|
| `test_ndarr.py` | `tinytorch.ndarr`（`NdArray` / `Shape`） |
| `test_autograd.py` | `tinytorch.autograd`（`Tensor` / `Function` / `no_grad`） |
| `test_nn.py` | `tinytorch.nn` 的核心（`Module` / `Parameter` / `Sequential` / `ModuleList` / `Linear` / 基础激活） |
| `test_advanced_layers.py` | `tinytorch.nn.layers` 的进阶层（`Conv2d` / `LayerNorm` / `Dropout` / `Embedding` / `MultiHeadAttention`） |
| `test_rnn_layers.py` | `tinytorch.nn.layers.rnn`（`RNN` / `LSTM` / `GRU`） |
| `test_losses.py` | `tinytorch.ml.losses`（`MSELoss` / `CrossEntropyLoss` / `BCELoss`） |
| `test_optimizers.py` | `tinytorch.ml.optimizers`（`SGD` / `Adam` / `Optimizer` 基类） |
| `test_dataloader.py` | `tinytorch.utils.data`（`Dataset` / `DataLoader` / `Sampler`） |
| `test_training.py` | `tinytorch.ml.trainer` 等训练组件（`Trainer` / `Model` / `Monitor` / `EarlyStopping` / 评估器） |
| `test_integration.py` | 跨模块端到端验证（训练闭环、`state_dict` 往返等） |

> 📌 目前仓库**没有**单独的 `test_evaluators.py`：`tinytorch/ml/evaluators/` 下的评估器（`Accuracy` 等）由 `test_training.py` 覆盖。新增评估器时可在 `test_training.py` 追加，也可以单独新建 `test_evaluators.py`（记得在此表补一行）。

`pytest` 配置（`pyproject.toml` 中 `[tool.pytest.ini_options]`）：

- `testpaths = ["tests"]`
- `python_files = ["test_*.py"]`
- `python_classes = ["Test*"]`
- `python_functions = ["test_*"]`
- `addopts = ["--verbose", "--strict-markers", "--tb=short"]`

### 11.5.2 新增测试的最低标准

新增或修改代码时，至少要覆盖：

1. **正常路径**：典型输入 → 期望输出；
2. **边界情况**：空形状、单元素、`dtype` 切换等；
3. **异常路径**：非法输入是否抛出预期异常（用 `pytest.raises`）；
4. **梯度正确性**：若修改自动微分相关代码，**必须**调用 `tests/helpers.py` 中的 `gradcheck` 验证解析梯度与中心差分数值梯度一致。

### 11.5.3 测试工具（`tests/helpers.py`）

不要直接手工构造 `NdArray` / `Tensor`，优先使用项目自带的辅助工具（降低样板、统一容差）：

| 工具 | 用途 |
|------|------|
| `make_ndarray(data, dtype='float32')` | 从嵌套列表快速构造 `NdArray` |
| `make_tensor(data, requires_grad=True, name=None, dtype='float32')` | 快速构造 `Tensor` |
| `assert_close(actual, expected, rtol=1e-4, atol=1e-5)` | 标量近似相等 |
| `assert_ndarray_close(actual, expected, rtol=1e-4, atol=1e-5)` | 逐元素比较两个 `NdArray` |
| `numerical_grad(fn, inputs, eps=1e-4)` | 中心差分计算数值梯度 |
| `gradcheck(fn, inputs, eps=1e-4, rtol=1e-2, atol=1e-3)` | 对比解析梯度 vs 数值梯度 |

### 11.5.4 gradcheck 示范

给**新算子**补梯度测试的模板：

```python
from tests.helpers import make_tensor, gradcheck

def test_my_op_grad():
    x = make_tensor([[1.0, 2.0], [3.0, 4.0]])
    y = make_tensor([[0.5, 1.5], [2.5, 3.5]])
    # fn 必须返回一个标量 Tensor
    gradcheck(lambda a, b: (a.mul(b)).sum(), [x, y])
```

> ⚠️ `gradcheck` 内部会跑一次解析 backward 与两次数值前向。纯 Python 下开销较大，单个用例建议张量规模控制在 **几十到一两百个元素**。

### 11.5.5 覆盖率门槛

```bash
pytest --cov=tinytorch --cov-report=term-missing
```

- **核心包**（`ndarr` / `autograd` / `nn`）期望维持 **≥ 85%** 行覆盖率；
- 新增的公共 API 期望覆盖率 **100%**；
- `examples/` 和 `tests/` 本身不纳入覆盖率统计（已在 `[tool.coverage.run]` 的 `omit` 中排除）。

## 11.6 提交 & Pull Request 规范

### 11.6.1 Commit 信息

采用 **Conventional Commits** 风格：

```
<type>(<scope>): <subject>

<body>

<footer>
```

**`<type>`** 枚举（与分支前缀对齐）：`feat` / `fix` / `docs` / `test` / `refactor` / `perf` / `chore`。

**示例**：

```
feat(autograd): add Softmax function with gradcheck

- 新增 tinytorch/autograd/ops/activation.py::Softmax
- 反向按 Jacobian 向量积的闭式推导实现
- tests/test_autograd.py 补充 gradcheck 用例

Closes #42
```

规则：

- `subject` 用祈使句、小写开头、不加句号，控制在 **72 字符**内；
- `body` 解释**为什么**这样改，而不是**做了什么**（后者看 diff 即可）；
- 引用 issue 用 `Closes #n` / `Refs #n`。

### 11.6.2 PR 自查清单

开 PR 前请自查：

- [ ] 分支已 rebase 到最新 `upstream/main`
- [ ] `ruff check .` 无错
- [ ] `python run_tests.py` 全绿
- [ ] 新增 / 修改代码有**对应的测试**
- [ ] 修改的 `docstring` 保持与实际行为一致
- [ ] 未引入任何运行时第三方依赖
- [ ] 若改动了公共 API，已同步更新 `wiki/` 下相应文档
- [ ] Commit 信息符合约定

### 11.6.3 PR 模板

> 可复制到 PR 描述里，按需删除不相关章节。

```markdown
## 动机
<!-- 这次改动解决什么问题？关联哪个 issue？ -->

## 改动说明
<!-- 主要改了哪些模块？关键设计权衡是什么？ -->

## 测试
<!-- 新增 / 修改了哪些测试？如何手工验证？ -->

## 兼容性
<!-- 是否引入破坏性变更？迁移路径是什么？ -->

## 文档
<!-- 是否同步更新了 wiki / docstring？ -->

## Checklist
- [ ] 本地 `ruff check .` 通过
- [ ] 本地 `python run_tests.py` 通过
- [ ] 新代码 100% 被测试覆盖
- [ ] 不引入第三方运行时依赖
```

### 11.6.4 Review 流程

- 维护者通常在 **3 个工作日**内给出首次 review。
- 若有修改意见，请**追加 commit**（不要强推覆盖历史），便于 reviewer 看到增量变化；合并前会由维护者 squash。
- 连续 14 天没有作者回复的 PR 会被标记 `stale` 并关闭；再开继续即可。

## 11.7 发布流程（维护者）

本节面向 **有合并权限** 的维护者，普通贡献者可跳过。

1. 确认 `main` 在 CI 上全绿；
2. 在 `pyproject.toml` / `tinytorch/__init__.py::__version__` 同步升级版本号（遵循 **Semver**）：
   - `MAJOR`：破坏性 API 变更；
   - `MINOR`：向后兼容的新特性；
   - `PATCH`：向后兼容的 bug 修复与文档。
3. 在 `CHANGELOG`（若后续新增）中追加本版本的 `Added / Changed / Fixed / Removed` 条目；
4. 在 GitHub 打 tag：`git tag v0.x.y && git push upstream v0.x.y`；
5. 构建发布包：
   ```bash
   pip install build twine
   python -m build
   twine check dist/*
   # twine upload dist/*        # 如已开启 PyPI 发布
   ```
6. 在 Release 页面撰写发布说明，附上主要变更与迁移指引。

## 11.8 特殊贡献指引

### 11.8.1 新增算子（`Function`）

1. **放置位置**：`tinytorch/autograd/ops/<category>.py`，对照当前已存在的分类文件选择：

   | 文件 | 用途 |
   |------|------|
   | `basic.py` | 四则运算（`Add` / `Sub` / `Mul` / `Div` / `Neg`） |
   | `math_ops.py` | `Exp` / `Log` / `Sqrt` / `Pow` 等标量函数 |
   | `matrix.py` | `MatMul` / `Transpose` / `Reshape` |
   | `reduce.py` | `Sum` / `Mean` / `Max` / `Min` 等归约 |
   | `activation.py` | `ReLU` / `Sigmoid` / `Tanh` / `LeakyReLU` |
   | `conv.py` | 卷积族（`Conv2d` 对应的前/反向算子） |
   | `nn.py` | 为特定层提供的复合算子 |
   | `loss.py` | 损失函数的可微分实现 |
   | `utils.py` | 算子内部共享的辅助函数（如 `broadcast_backward`、`DEFAULT_EPSILON`） |

   若已有分类都不合适，可以新建一个文件，并在 `tinytorch/autograd/ops/__init__.py` 补充导出。

2. **必须实现**：
   - `forward(*inputs: NdArray) -> NdArray`（或 `Tuple[NdArray, ...]`）；
   - `backward(grad_output: NdArray) -> List[NdArray]`；
   - 在 `forward` 内调用 `self.save_for_backward(...)` 保存反传需要的张量。
3. 在 `Tensor` 上暴露便捷方法（如需要），并通过**延迟导入**避免循环依赖（参考现有算子的写法，如 `tensor.py` 里 `_OPS_BASIC` 等模块路径常量）。
4. 在 `tests/test_autograd.py` 补 `gradcheck` 用例（按算子分类追加到现有的 `TestBasicOps` / `TestMathOps` / `TestMatrixOps` / `TestReduceOps` / `TestActivationOps` 对应的测试类里，保持组织一致）。
5. 在 `wiki/05-Autograd模块.md` 和 `wiki/09-API参考文档.md` 补签名。

### 11.8.2 新增层（`Module` 子类）

1. **放置位置**：`tinytorch/nn/layers/<your_layer>.py`，并在 `tinytorch/nn/layers/__init__.py` 导出。对照当前已有分类选择新文件或追加到合适的现有文件：

   | 文件 | 已含层 |
   |------|--------|
   | `linear.py` | `Linear` |
   | `activation.py` | `ReLU` / `Sigmoid` / `Tanh` / `LeakyReLU` |
   | `normalization.py` | `LayerNorm` |
   | `dropout.py` | `Dropout` |
   | `embedding.py` | `Embedding` |
   | `conv.py` | `Conv2d` |
   | `rnn.py` | `RNN` / `LSTM` / `GRU` |
   | `attention.py` | `MultiHeadAttention` |

2. **必须实现**：
   - `__init__(...)`：调用 `super().__init__(name=...)` 并注册参数 / 缓冲区；
   - `forward(input: Tensor, ...) -> Tensor`：严禁绕过自动微分（不得直接操作 `NdArray`，所有可微分计算必须走 `Tensor` / `Function`）；
   - 形状校验：不匹配时 `raise ValueError` 并附形状信息。
3. 在 `tests/test_nn.py` 或 `test_advanced_layers.py` 中添加：
   - 前向形状测试；
   - 反向 `gradcheck`（需要把层包在一个返回标量的函数里，见 11.5.4）；
   - 参数数量与 `state_dict` 序列化往返测试。
4. 更新 `wiki/06-神经网络nn模块.md` 的层一览表。

### 11.8.3 新增示例（`examples/`）

- 每个示例必须**自成一个 `.py` 文件**即可运行，不依赖外部数据下载（如需数据，请在代码开头用纯 Python 生成）；
- 开头加文档字符串说明：背景、数据构造、预期输出；
- 尽量控制单次运行时长在 **1 分钟内**（纯 Python 下，batch 和 epoch 都要压小）；
- 严禁 `print("..."); exit()` 类的调试残留。
